# 뉴스 쇼츠

뉴스 리포트 한 꼭지를 40–60초 세로 쇼츠로 다시 만드는 형식입니다. 줄거리 요약(`recap-*.md`)과 같은 도구를 쓰지만 **재미보다 정확성이 먼저**입니다. 사실·인용·숫자·날짜·출처가 원문과 하나라도 다르면 실패입니다. 다른 매체의 원고·말투·화면 디자인을 베끼지 않고 문장은 원문 사실로 새로 씁니다.

본편 문서(`recap-highlight.md`)에서 그대로 쓰는 것: 자료 확인과 대사 뽑기(§0.5·§1), 장면 나누기, 알아볼 수 없는 장면 빼기(§1.1), 자막(§5), 목소리 일관성(§3.2). 쓰지 않는 것: 궁금증 설계·반전·cliffhanger, 반응·재치 줄, 화려한 효과음·장면 전환.

## 0. 두 가지 경우

| | 자사 원본 쇼츠 (`origin: "own"`, 기본·대부분) | 기사 기반 재구성 (`origin: "article"`) |
|---|---|---|
| 재료 | 매체가 직접 찍은 영상, 자사 방송 리포트 클립 | 기사·보도 내용 + 우리 내레이션 + AI 영상·자료 화면 |
| 소리 | 기자·앵커 원음, 현장음, 인터뷰 원음이 주인공 | 새 내레이션 |
| 화면 | 원본 그대로(원본의 하단 이름표·자막도 그대로 둠) | 장면마다 **출처·성격 표시**("자료화면", "AI 생성 영상", "출처: 매체명") |
| 로고 | 사용자가 올린 자사 로고만 | 사용자가 올린 자사 로고만, 원 보도 매체는 글자로 출처 표시 |

- 자사 원본은 원본의 하단 이름표·워터마크를 자르지 않습니다(본편 §4.2 로고 띠 자르기는 쓰지 않음). 남의 방송 화면이 섞여 있으면 사용자에게 사용 권리를 먼저 확인합니다.
- 재구성에서 AI 영상은 **분위기·일반 장면**(도시 전경, 서류, 그래프 배경)에만 씁니다. 실제 인물·실제 사건 현장을 AI로 재현하지 않습니다. 그런 장면은 자료 화면이나 그래픽으로 바꿉니다.
- 새 내레이션을 AI 목소리로 만들면 매체 정책에 따라 "AI 음성" 표시를 넣습니다(사용자에게 확인).

## 1. 구조: 리드 → 사실 → 원문 → 맥락 → 마무리

| 단계 (`stage`) | 하는 일 | 모양 (예시는 새로 지은 문장) |
|---|---|---|
| 리드 `lead` | 가장 중요한 사실 한 문장. 누가·무엇을·언제 | "강변 다리 보수 공사가 3주 앞당겨 시작됩니다." |
| 사실 `fact` | 확인된 사실, 숫자, 경과 (여러 번) | "안전 점검에서 균열 12곳이 확인됐기 때문입니다." |
| 원문 `quote` | 당사자·관계자 발언 원음 (여러 번 가능) | 원음 + 하단 이름표, 내레이션 없음 |
| 맥락 `context` | 왜 중요한지, 배경, 비교 | "이 다리는 하루 버스 노선 4개가 지납니다." |
| 마무리 `close` | 다음 일정·남은 쟁점·확인된 결과 | "공사 기간에는 버스 4개 노선이 우회합니다." |

- 첫 3초 안에 리드가 끝납니다. 질문으로 시작하거나 결론을 감추지 않습니다.
- 마무리는 담담하게. "과연 어떻게 될까요?" 같은 궁금증 끝맺음, 시청자 반응 유도를 쓰지 않습니다.

## 2. 다섯 유형 (`newsType`)

| `newsType` | 언제 | 길이 | 다른 점 |
|---|---|---|---|
| `breaking` 속보 | 막 일어난 일 | 45초 안 | 제목 위 꼬리표 `tag: "속보"`, 확인된 것만. "확인 중"인 것은 그렇게 말함 |
| `explainer` 원인 설명 | 왜 이런 일이 생겼나 | 75초 안 | 사실 → 원인 2–3개 → 맥락. 원인마다 출처 |
| `investigative` 탐사·단독 | 자사 취재로 새로 드러난 사실 | 90초 안 | `tag: "단독"`, 문서·인터뷰 원문 비중이 큼, 반론·해명도 넣음 |
| `brief` 경제·데이터 브리핑 | 지표·발표·시장 | 60초 안 | 숫자는 데이터 카드로, 단위·기준일 표기 |
| `story` 사연·인물 | 사람 이야기 | 75초 안 | 감정은 당사자 원음으로, 내레이션은 사실만 |

## 3. 문장 규칙

- **인용은 원문 그대로.** 따옴표 안은 글자를 바꾸지 않습니다. 줄일 때는 앞뒤만 자르고 말줄임으로 뜻을 바꾸지 않습니다. 제목의 큰따옴표도 같습니다.
- **숫자·날짜·이름·직함은 원문과 대조.** 단위·반올림까지. 오래된 뉴스를 새 뉴스처럼 보이게 하지 않도록 보도 날짜를 화면에 남깁니다.
- **의견·과장어를 쓰지 않습니다**("충격", "경악", "역대급", "발칵" 등). 사실과 숫자로 보여 줍니다. 인용 안에 있는 말은 괜찮습니다.
- **누가 말했는지 붙입니다.** 확인되지 않은 것은 "~라고 밝혔습니다", "~로 전해졌습니다"처럼 출처를 붙이고 단정하지 않습니다.
- **수사·재판 중인 일**은 단계를 정확히(입건·송치·기소·판결). 혐의를 받는 사람을 범인처럼 쓰지 않고, 한쪽 주장만 있으면 반론·해명 여부를 적습니다.
- **일반인은 보도된 범위만.** 이름·얼굴·사는 곳을 원 보도보다 더 드러내지 않습니다. 피해자·미성년자는 특히.
- 반응·재치·평가 줄(`wit`·`reaction`·`review`)과 반전 연출을 쓰지 않습니다.

## 4. 화면 (9:16, `variant: "news"`)

```
┌──────────────────────┐
│      [속보]            │  ← tag: 빨간 꼬리표 (선택)
│  강변 다리 보수        │  ← 남색 띠, 굵은 고딕 2줄 헤드라인
│  3주 앞당겨 시작       │     1줄 흰색 → 2줄 하늘색, 강조 단어는 {yellow|…}
├──────────────────────┤
│                      │
│    16:9 원본 영상      │  ← 자르지 않고 폭에 맞춤 (원본 하단 이름표 그대로)
│                      │
├──────────────────────┤
│  기자·앵커 음성 자막    │  ← 굵은 흰 글자, 영상 아래 띠 (원본 자막과 겹치지 않음)
│                      │
│      매체명·로고        │  ← show.title / show.logoClipId (자사 것만)
│   2026.11.19 · 프로그램 │  ← show.tagline (날짜·프로그램)
└──────────────────────┘
```

- 헤드라인은 한 줄 12자 안팎, 2줄. 핵심 사실 + 따옴표 인용 하나 정도. 리드와 같은 사실이어야 합니다(낚시 제목 금지).
- 띠 색 기본 남색(`#0B1736`), 글꼴 기본 NanumSquareNeo 900. 사용자의 매체 디자인 규칙이 있으면 `bandColor`·`lineColors`·`font`로 맞춥니다.
- 계산은 `templates/shorts-layout.mjs`(`node shorts-layout.mjs news "줄1" "줄2"`), 앱은 `apply_shorts_layout { variant: "news" }`.

## 5. 기획 데이터와 검사

```json
{
  "mode": "news",
  "newsType": "explainer",
  "origin": "own",
  "durationSec": 50,
  "source": { "outlet": "자사 매체명", "date": "2026-11-19" },
  "headline": ["강변 다리 보수", "3주 앞당겨 시작"],
  "transcript": "원본 리포트 자막 또는 기사 본문 전체",
  "people": [{ "name": "담당 과장", "public": true }],
  "beats": [
    { "stage": "lead", "narration": { "role": "lead", "text": "강변 다리 보수 공사가 3주 앞당겨 시작됩니다." }, "src": { "from": 0, "to": 4 } },
    { "stage": "fact", "narration": { "role": "fact", "text": "안전 점검에서 균열 12곳이 확인됐기 때문입니다." }, "src": { "from": 10, "to": 14 } },
    { "stage": "quote", "quote": { "speaker": "담당 과장", "text": "안전 점검에서 균열 12곳이 확인됐다" }, "src": { "from": 20, "to": 24 } },
    { "stage": "close", "narration": { "role": "situation", "text": "공사 기간에는 버스 4개 노선이 우회합니다." }, "src": { "from": 30, "to": 34 } }
  ]
}
```

재구성(`origin: "article"`)이면 장면마다 `"footage": { "kind": "ai" | "archive" | "stock" | "graphic" | "own", "label": "AI 생성 영상" }`을 적습니다. 숫자를 카드로 보일 beat는 `"data": "균열 12곳"`.

`node templates/recap-plan.mjs check plan.json`(앱 `check_recap_plan`)이 보는 것:

- 오류: `source.outlet`·`source.date` 없음, lead로 시작하지 않음, fact 없음, 인용(`quote.text`·따옴표 안)이 `transcript`·`dialogueText`에 글자 그대로 없음, 재구성인데 AI·자료 장면에 `footage.label` 없음, AI 표시에 "AI" 없음, AI로 실제 인물·현장 재현(`realPerson`·`realEvent`), 일반인 이름이 원문에 없음.
- 경고: `newsType` 없음, 유형별 길이 초과, 속보인데 꼬리표 없음, 원문에 없는 숫자, 의견·과장어, 반응·재치·평가 줄, 발언 구간 내레이션, 발언자 없음, close·context로 끝나지 않음, 자사 원본인데 내레이션이 80% 넘음, transcript 없음(대조 못 함).

`finish`(마무리 후보)는 뉴스에서 효과음·장면 전환을 거의 쓰지 않고 정보 그래픽만 냅니다: 발언 하단 이름표(원본에 이미 있으면 생략), 데이터 카드, 재구성 영상 출처 표시(필수), 첫 2초 날짜·매체 칩, 속보 알림음 하나.

## 6. MCP 진행 순서

1. **재료 확인**: 사용자가 올린 자사 리포트 클립과 원고·기사 본문을 받습니다. 원고가 없으면 `transcribe_clip`으로 뽑아 `transcript`로 씁니다. 날짜·매체·발언자 직함을 사용자에게 확인합니다.
2. `detect_scenes`·`view_shot_sheet`로 장면을 나누고, 리드·사실·발언·맥락 장면을 고릅니다.
3. 기획 beat 표 → `check_recap_plan { plan: { mode: "news", newsType, origin, source, headline, transcript, beats } }` → 오류가 없을 때까지 고침 → 사용자(데스크) 확인. 사실 확인의 최종 책임은 매체에 있음을 알립니다.
4. `update_project_settings`로 1080×1920 → `place_story_shots { clipId, shots }`(발언 beat는 `keyLine`으로 원음 1, 나머지도 기자 원음을 살림).
5. 재구성이면 AI 영상(`footage-gen.md`, 분위기 장면만)·자료 화면을 놓고, 새 내레이션은 `ai.voice.generate`(한 목소리, 차분하게) → `check_voice_consistency`.
6. 자막(본편 §5): 원음·내레이션을 문장 그대로, 맞춤법만 고침.
7. `apply_shorts_layout { variant: "news", title: ["줄1", "줄2"], tag?, show: { title: 매체명 | logoClipId, tagline: "날짜 · 프로그램" }, subtitleClipIds, sourceLabels?: [{ clipId, text: "AI 생성 영상" }] }`.
8. BGM은 없거나 아주 낮게(원음 −20dB 아래). 마무리 후보(`finishing`) 중 이름표·데이터 카드·출처 표시만.
9. 검수.

## 7. 검수 체크리스트

- [ ] 리드가 첫 3초 안에 핵심 사실을 말하고, 헤드라인과 같은 사실이다.
- [ ] 따옴표 인용·숫자·날짜·이름·직함이 원문과 글자 그대로 맞다.
- [ ] 의견·과장어, 반응·재치 줄, 궁금증 끝맺음이 없다.
- [ ] 확인되지 않은 내용에 출처가 붙어 있고 단정하지 않는다. 수사·재판 단계가 정확하다.
- [ ] 일반인·피해자·미성년자 정보가 원 보도보다 더 드러나지 않는다.
- [ ] 화면에 매체명(또는 자사 로고)과 보도 날짜가 있다. 로고는 사용자가 올린 자사 것만.
- [ ] 재구성이면 AI·자료 장면마다 출처·성격 표시가 그 장면 내내 보이고, AI로 실제 인물·현장을 재현하지 않았다.
- [ ] 아래 띠 자막이 원본 영상 안 자막·이름표와 겹치지 않는다.
