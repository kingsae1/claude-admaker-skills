# 시간순 해설형 줄거리 요약

영화·드라마 한 편 전체를 **처음부터 끝까지 원작 순서대로** 친근한 내레이션으로 풀어 주는 형식입니다. 내레이션이 사건을 끌고 가고, 원작 장면과 대사는 그 이야기를 보강합니다. 특정 채널의 대본·말투·브랜딩을 흉내 내지 않고, 문장은 매번 새로 씁니다.

본편 문서(`recap-highlight.md`)에서 그대로 쓰는 것: 사전 조사(§0.5), 대사 뽑기·장면 나누기(§1), 알아볼 수 없는 장면 빼기(§1.1), 배우 대사 강조(§4.1), 로고·자막 띠 자르기(§4.2), 전환·줌 검토(§4.3), 자막(§5), 소리(§6), 목소리 일관성(§3.2), 윤문(§3.1), 마무리 효과 패스(§8.2). 이 문서는 그와 다른 점만 적습니다.

## 1. 세 가지 줄거리 형식

| | 궁금증 설계형 (`recap-highlight.md`) | 시간순 해설형 (이 문서) | 쇼츠 (`recap-shorts.md`) |
|---|---|---|---|
| 순서 | 결과·모순을 먼저, 순서를 재배치 | 원작 순서대로(회상은 한 번까지) | 한 상황만 |
| 내레이션 | 정보를 나눠 공개하며 이야기를 이끎 | 거의 모든 장면을 설명하며 이끎 | 필요한 곳에만 한 문장 |
| 원작 대사 | 결정적 대사만 강조 | 장면을 살리는 보조 | 주인공 |
| 긴장 | 질문 장부·반전 반복 | 시간순 위에 의심·질문·"알고 보니" 반전 | 대사의 주고받음 |
| 끝 | 다음 궁금증(cliffhanger) | 결말 + 주인공의 마지막 상태 + 작품명 | 그 장면의 재미 |
| 잘 맞는 원작 | 스릴러·미스터리·반전물 | 인물 드라마·성장물·감정선이 긴 영화, 처음 보는 사람용 전체 요약 | 코미디·사이다 장면 |

사용자가 형식을 정하지 않았으면 원작 장르와 길이로 하나를 추천하고 `ask_user_choice`로 고르게 합니다. 미스터리라도 "결말까지 한 번에 알고 싶다"면 시간순 해설형 위에 의심·반전 줄을 얹습니다(§4).

## 2. 일곱 단계

| 단계 (`stage`) | 하는 일 | 내레이션 모양 |
|---|---|---|
| (선택) 예고 `hook` | 3–5초, 가장 센 장면 하나를 맛보기로 | 없음 또는 질문 한 줄 |
| 인물 소개 `intro` | 주인공의 이름·지금 상황·특징 | "지금 하는 행동 + 이름"으로 소개 |
| 사건 발생 `incident` | 주인공에게 일어난 핵심 사건 | 상황 설명 |
| 사건의 연속 `sequence` | 인물의 행동과 주변 반응을 순서대로 (여러 번) | 잇는 말 + 행동 설명, 가끔 구어체 한마디 |
| 관계·갈등 확대 `conflict` | 새 인물, 예상 밖 행동, 갈등 | 인물 해석, 질문형 |
| 반전·위기 `twist` | 숨겨진 사실 공개나 더 큰 위기 (작은 반전 여러 번 가능) | "알고 보니 / 사실 / 그런데" |
| 결말 `ending` | 사건의 결과와 주인공의 변화 | 감정 정리 |
| 마무리 `outro` | 주인공의 마지막 모습 + 작품명 | "그렇게 ~하며 영화는 끝이 납니다", "지금까지 ○○였습니다" |

길이 기준: 3–5분은 sequence·conflict를 4–6번, 반전 1–2번. 10분 넘으면 장(章)마다 짧은 장 제목을 둡니다.

## 3. 내레이션 다섯 갈래

시간순 해설형은 거의 모든 장면에 내레이션이 있으므로, **문장마다 다섯 갈래 중 하나**를 정해 리듬을 만듭니다. 같은 갈래가 길게 이어지면 지루해집니다.

| 갈래 | 역할 (`role`) | 하는 일 | 모양 (예시는 새로 지은 문장) |
|---|---|---|---|
| 장면 설명 | `situation` | 무슨 일이 일어났는지 | "새벽마다 같은 버스를 타는 남자 민호." |
| 인물 설명 | `character`·`emotion` | 특징과 심리 변화 | "이제야 혼자라는 게 실감 나는 민호." |
| 장면 연결 | `transition`·`causal` | 다음 사건으로 넘김 | "그때 맨 뒷자리에서 한 여자가 일어나는데" |
| 구어체 한마디 | `wit` | 행동을 관찰하는 친근한 반응 | "길 잃은 건 버스인데 사과는 민호가 하네요." |
| 궁금증 | `suspense`·`withhold`·`twist` | 질문, 정보 미루기, 추측 고치기 | "지아는 정말 처음 보는 사람일까요?" → "알고 보니 옛 동창이었죠." |

말투 규칙:

- **이름으로 끝나는 짧은 명사 문장**("~하는 민호.")과 **"~죠 / ~는데 / ~네요"** 구어 끝맺음을 섞습니다. 한 편 안에서 존댓말 톤을 통일합니다.
- 문장 앞 **잇는 말**: 그때·한편·그런데·그렇게·이제·다음 날·결국·마침내·알고 보니·사실. 장면이 바뀌는 줄의 4분의 1 이상은 잇는 말로 시작하되, 같은 말("그렇게")을 3번 연달아 쓰지 않습니다.
- 구어체 한마디(`wit`)는 양념입니다. 90초 넘는 영상에 한두 번, 내레이션 줄의 30% 아래.
- 인물이 처음 나올 때는 내레이션에 **이름을 꼭** 넣고, 설명보다 지금 하는 행동으로 소개합니다.
- 배우 대사 강조(§4.1) 구간에는 내레이션을 얹지 않고 대사 앞뒤 쉼에 둡니다.
- 한 beat는 한두 문장, 문장마다 갈래 하나.

## 4. 시간순 위에 의심과 반전 얹기

순서는 원작 그대로지만 정보를 말하는 순서는 고를 수 있습니다.

1. 수상한 단서나 행동을 먼저 보여 주고 **추측을 만듭니다**(`suspense` 질문 한 줄 또는 `withhold`).
2. 몇 장면 뒤에 "알고 보니 / 사실"로 **추측을 고칩니다**(`twist`, `reveal: "recontext"`).
3. 가짜 단서와 진짜 위협을 번갈아 두면 긴장이 이어집니다. 작은 반전은 1–2분에 하나.

반전 앞에 의심·질문이 없으면 검사에서 경고합니다.

## 5. 기획 데이터와 검사

본편과 같은 JSON(`recap-highlight.md` §2.6)에 `"mode": "chrono"`로 씁니다. `events`(원작 시간순)는 순서 확인에 씁니다.

```json
{
  "mode": "chrono",
  "durationSec": 240,
  "title": "작품명",
  "events": [ { "id": "E1", "chrono": 1, "characters": ["민호"], "summary": "…" } ],
  "beats": [
    { "stage": "intro", "event": "E1", "narration": { "role": "situation", "text": "새벽마다 같은 버스를 타는 남자 민호." }, "src": { "from": 12.0, "to": 16.4 } },
    { "stage": "incident", "event": "E2", "narration": { "role": "situation", "text": "그런데 그날 버스가 종점을 지나쳐 버리는데" }, "src": { "from": 95.2, "to": 99.0 } },
    { "stage": "conflict", "event": "E5", "narration": { "role": "suspense", "text": "지아는 정말 처음 보는 사람일까요?" }, "src": { "from": 1210.0, "to": 1214.5 } },
    { "stage": "twist", "event": "E6", "reveal": "recontext", "narration": { "role": "twist", "text": "알고 보니 지아는 민호가 잊은 옛 동창이었죠." } },
    { "stage": "outro", "narration": { "role": "outro", "text": "지금까지 작품명이었습니다." } }
  ]
}
```

`node templates/recap-plan.mjs check plan.json`(앱 `check_recap_plan`)이 보는 것: intro로 시작(짧은 hook 예고 뒤까지), incident 있음, ending·outro로 끝남, 원작 순서를 거슬러 간 곳 한 번까지, 내레이션 beat 70% 이상, 잇는 말 비율과 같은 잇는 말 반복, wit 양, 반전 앞 의심·질문, 인물 첫 등장 줄에 이름, 감정 4연속, 문장 수. `shots`는 앱 단계로 바꿔(intro → setup, incident → inciting, sequence·conflict → escalation, ending·outro → payoff) 넘깁니다. `finish`는 마무리 효과 후보(인물 이름표, 작품명 카드 등)를 줍니다.

## 6. MCP 진행 순서

1. 본편 §8의 1–3번(확인, 사전 조사, 대사 뽑기, 장면 나누기, 알아보기, 로고 띠)을 그대로.
2. 원작 시간순 사건표를 만들고, 일곱 단계 beat 표(단계·사건·내레이션 갈래·문장·장면)를 써서 `check_recap_plan { plan: { mode: "chrono", … } }`로 검사 → 사용자 확인.
3. 윤문(본편 §3.1): 줄을 이어 읽어 잇는 말이 자연스럽고, 앞에서 말하지 않은 인물·사실이 갑자기 나오지 않는지.
4. `ai.voice.generate`(한 목소리, 같은 스타일 태그) → `check_voice_consistency` → `place_story_shots { clipId, shots }`(결과 shots 그대로) → 자막 → BGM 덕킹.
5. 마무리 효과 패스(본편 §8.2, `finishing`) → 검수.

## 7. 검수 체크리스트

- [ ] 원작 순서대로 흘러가고, 처음 보는 사람도 인물과 사건을 따라갈 수 있다.
- [ ] 인물이 처음 나올 때 이름과 지금 하는 행동이 같이 나온다.
- [ ] 장면이 바뀔 때 잇는 말이 자연스럽고, 같은 잇는 말이 연달아 반복되지 않는다.
- [ ] 구어체 한마디는 한두 번, 사건 설명을 가리지 않는다.
- [ ] 반전 앞에 의심이나 질문이 있고, 반전 줄은 "알고 보니 / 사실"로 앞의 추측을 고친다.
- [ ] 결말에서 주인공의 마지막 상태를 정리하고 작품명 한 줄로 끝난다.
- [ ] 배우 대사 강조 구간에 내레이션이 겹치지 않는다.
