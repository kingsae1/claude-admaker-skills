# 줄거리 쇼츠 (대사 중심 짧은 영상)

긴 원본(드라마·영화·웹드라마 회차, 자체 시리즈)에서 **한 상황, 한 갈등**만 골라 15–60초 세로 영상으로 만드는 형식입니다. 본편 하이라이트(`recap-highlight.md`)는 내레이션이 이야기 전체를 다시 짜서 이끌지만, 쇼츠는 **원작 대사와 장면이 주인공**이고 내레이션은 필요한 곳에만 짧게 들어갑니다. 특정 채널의 대본·말투·브랜딩을 흉내 내지 않고, 대본은 매번 새로 씁니다.

> 좋은 쇼츠 내레이션은 말을 많이 만드는 것이 아니라, **말하지 않아도 되는 구간을 정확히 찾는 것**입니다.

본편 문서에서 그대로 쓰는 것: 사전 조사(§0.5), 대사 뽑기·장면 나누기(§1), 알아볼 수 없는 장면 빼기(§1.1), 배우 대사 강조(§4.1), 로고·자막 띠 자르기(§4.2), 전환·줌 검토(§4.3), 자막(§5), 목소리 일관성(§3.2). 이 문서는 그와 다른 점만 적습니다.

## 1. 본편과 다른 점

| | 본편 하이라이트 | 쇼츠 |
|---|---|---|
| 내레이션 | 사건과 인과관계를 이어 이야기를 이끎 | 필요한 곳에만, 한 문장씩 |
| 원작 대사 | 이야기를 전하는 수단 | 주된 콘텐츠 |
| 정보 | 여러 단계로 나눠 공개 | 핵심 상황만 압축 |
| 재미 | 반전·긴장·감정 변화 | 재치 있는 상황과 대사 |
| 전개 | 사건을 쌓아 감 | 한 상황·한 갈등에 집중 |
| 끝 | 다음 사건을 궁금하게 | 그 장면의 재미를 완성 |

## 2. 장면 고르기

- 원본 전체에서 **대사만 봐도 웃기거나 놀랍거나 통쾌한 한 상황**(2–6개 장면)을 고릅니다. 앞뒤 맥락이 길게 필요한 장면은 쇼츠보다 본편에 씁니다.
- 고르는 기준: 첫 대사·첫 화면이 모순적이거나 특이한가, 대사의 주고받음만으로 갈등이 보이는가, 마지막에 터지는 한 마디나 행동이 있는가.
- 인물·상황을 알아볼 수 없는 장면은 쓰지 않습니다(본편 §1.1). 세로 9:16이면 말하는 얼굴이 화면 가운데 오게 `crop_clip`·focus로 맞춥니다.

## 3. 다섯 단계

| 단계 (`stage`) | 하는 일 | 내레이션 |
|---|---|---|
| 훅 `hook` | 가장 특이하거나 모순적인 대사·상황을 먼저 | 보통 없음(대사로 시작). 필요하면 짧은 질문 한 줄 |
| 맥락 `context` | 장면을 이해하는 데 꼭 필요한 정보만(인물 정체, 배경) | 1–2문장 |
| 대사 `dialogue` | 인물의 행동과 대사로 갈등·재미를 직접 전달 | **없음** |
| 해석 `commentary` | 인물의 황당한 논리나 예상 밖 행동을 한 문장으로 재치 있게 풀기 | 한 문장, 한두 번만 |
| 마무리 `payoff` | 반전·황당한 대사·통쾌한 행동으로 끝냄 | 보통 없음. 여운이 필요할 때만 한 줄 |

길이: 15–30초는 hook → (context) → dialogue → payoff, 30–60초는 dialogue와 commentary를 1–2번 번갈아 둡니다. 쇼츠는 다음 궁금증(cliffhanger)으로 끝내지 않아도 됩니다.

## 4. 내레이션을 넣을지 판단하기

beat마다 아래를 순서대로 묻고, 하나도 해당하지 않으면 **내레이션을 넣지 않습니다**(`needsNarration: false`).

1. 이 장면은 대사만으로 이해되는가? → 된다면 넣지 않음.
2. 처음 보는 사람이 모를 배경(인물의 정체·관계·앞 사건)이 있는가? → `context` 한 줄.
3. 인물의 행동을 한 문장으로 해석하면 재미가 커지는가? → `commentary` 한 줄(`wit` 또는 `character`).
4. 내레이션보다 원작 대사를 그대로 보여 주는 편이 나은가? → 그렇다면 넣지 않음. 이 판단이 가장 중요합니다.

쇼츠에서 자주 쓰는 내레이션 모양:

| 모양 | 역할 (`role`) | 쓰는 곳 |
|---|---|---|
| 상황 압축 | `situation` | 인물의 설정과 모순된 행동을 한 줄로 |
| 도입 | `situation` | 상황의 시작을 한 문장으로 알리고 바로 대사로 |
| 재치 해석 | `wit` | 혼란스러운 상황을 짧게 비틀어 정리, 웃음은 다음 대사가 완성 |
| 인물 해석 | `character` | 인물의 태도·성격을 한 줄로 규정해 대사에 의미를 더함 |

## 5. 내레이션 규칙

1. **대사가 말한 내용은 되풀이하지 않습니다.** 이미 대사로 전해진 사실은 뺍니다.
2. **내레이션은 장면 사이의 빈 정보만 채웁니다.** 인물의 정체, 상황의 배경, 행동의 의미.
3. **한 문장에 역할 하나.** 상황 설명과 인물 평가와 유머를 한 문장에 몰아넣지 않습니다.
4. **재미있는 대사는 원작에 맡깁니다.** 모든 장면에 내레이션을 덧붙이지 않습니다. 내레이션이 있는 beat는 전체의 40% 이하.
5. **필요한 순간에만 해석합니다.** 황당한 논리나 예상 밖 행동을 한 문장으로 요약할 때 가장 효과적입니다.
6. 내레이션은 대사와 겹치지 않게 대사 사이의 쉼에 넣습니다. 대사 구간은 원본 소리를 1로(§4.1 `keyLine`), 내레이션 구간만 원본 소리를 낮춥니다.

말투는 본편과 같은 목소리·같은 스타일 태그를 쓰되(§3.2), 위트 줄은 조금 가볍게 끝을 올립니다. 해설체 현재형이나 가벼운 존댓말("~하죠", "~입니다") 중 하나로 한 편 안에서 통일합니다.

## 6. 화면

- 첫 1초 안에 말이나 소리가 나옵니다. 무음 도입·로고 인트로 없음.
- 컷은 대사 단위로. 대사 중간에 자르지 않고, 대사 사이 리액션 컷(0.5–1.2초)으로 리듬을 만듭니다.
- 썸네일 프레임은 표정이 가장 센 장면.

### 6.1 9:16 레이아웃 (위 띠 제목 · 가운데 영상 · 아래 띠 작품명)

줄거리 쇼츠에서 가장 흔한 화면 틀입니다. 가로 원본을 세로 화면에 넣을 때 위아래 남는 자리를 검은 띠로 두고, 띠에 제목과 작품 정보를 얹습니다.

```
┌──────────────┐  위 띠 22% (검정)
│  훅 제목 1줄  │  굵은 디스플레이 글꼴, 검은 외곽선, 영상 바로 위에 붙임
│  훅 제목 2줄  │  2줄 기본색: 1줄 형광 초록 → 2줄 노랑. 단어 하나만 빨강 등으로 강조 가능
├──────────────┤
│              │  영상 58% (가로 원본은 좌우를 잘라 채움, 말하는 얼굴이 가운데)
│   원본 영상   │
│  "대사 자막"  │  흰 글자 + 검은 외곽선, 영상 아래쪽 안
├──────────────┤
│    작품명     │  아래 띠 20% (검정). 작품명 크게 + 시청처 한 줄 작게
│  시청처 한 줄  │
└──────────────┘
```

| 칸 | 규칙 |
|---|---|
| 훅 제목 | 기획 hook beat의 `question`을 상황 한 줄로 줄여 씀(인물 이름보다 상황). 1–2줄, 한 줄 12자 안팎(14자 넘으면 글자가 작아짐). 결과물에 없는 내용을 약속하지 않음 |
| 제목 색 | 줄마다 한 색이 기본(흰색 · 형광 초록 · 노랑). 강조는 단어 1개만 `{red|1억}`처럼 감쌈. 색 이름: white·green·yellow·red·mint·orange·pink·sky 또는 #hex |
| 제목 글꼴 | 굵은 디스플레이 고딕(`Black Han Sans` 기본, `Gasoek One` 등). 외곽선은 글자 크기의 9% 안팎 |
| 영상 | 띠를 뺀 자리 비율로 원본을 잘라 채움(§4.2 로고·자막 띠를 먼저 잘라 낸 영역 안에서). 얼굴이 한쪽이면 `focusX` |
| 대사 자막 | 원작 대사가 주인공이라 크게(한 줄 12–16자), 흰 글자 + 검은 외곽선. 내레이션 자막은 대사 자막과 색·위치를 다르게 |
| 작품명·시청처 | 작품명은 사용자가 준 이름 그대로 글자로. 이름을 모르면 자리 표시 "작품명"을 두고 사용자에게 묻습니다. 방송사·채널·작품 로고 이미지는 사용자가 직접 올린 경우에만 그 자리에 맞춰 넣음 |

변형: `wide`(16:9 원본을 자르지 않고 폭에 맞춤, 위 띠 30%), `fullbleed`(영상이 화면 전체, 띠 없이 제목은 위 안전 여백, 대사 자막만). 원본이 세로이거나 얼굴이 화면을 꽉 채우는 장면이면 `fullbleed`.

특정 채널의 글꼴·색 조합·로고 배치를 그대로 따라 하지 않습니다. 위 틀은 형식이고, 색과 글꼴은 작품 분위기에 맞춰 고릅니다.

- 계산: `node templates/shorts-layout.mjs banded "줄1" "{red|강조} 줄2"` → 띠·영상·제목·자막·작품명 상자(px).
- MCP: 장면을 놓은 뒤 `apply_shorts_layout { title: ["줄1", "줄2"], show: { title, tagline }, variant }`. 영상 클립을 영상 자리로 잘라 맞추고, 배경을 검정으로, 제목·작품명 글자 클립을 새 행에 넣고, "대사 N" 자막을 흰 글자 + 검은 외곽선으로 바꿉니다.

## 7. 기획 데이터와 검사

본편과 같은 JSON(`recap-highlight.md` §2.6)에 `"mode": "shorts"`로 씁니다. `events`는 생략할 수 있고, beat마다 `dialogueText`(그 구간 원작 대사)와 `needsNarration`(§4 판단)을 적습니다.

```json
{
  "mode": "shorts",
  "durationSec": 40,
  "beats": [
    { "stage": "hook", "dialogueText": "…가장 모순적인 대사…", "needsNarration": false, "src": { "from": 812.4, "to": 815.0 } },
    { "stage": "context", "needsNarration": true,
      "narration": { "role": "situation", "text": "그는 이 섬에 하나뿐인 의사다." }, "src": { "from": 640.2, "to": 643.0 } },
    { "stage": "dialogue", "dialogueText": "…", "needsNarration": false, "src": { "from": 815.0, "to": 822.6 },
      "keyLine": { "text": "…" } },
    { "stage": "commentary", "narration": { "role": "wit", "text": "…한 줄 해석…" }, "src": { "from": 822.6, "to": 825.0 } },
    { "stage": "payoff", "dialogueText": "…", "needsNarration": false, "src": { "from": 830.1, "to": 834.0 } }
  ]
}
```

`node templates/recap-plan.mjs check plan.json`이 보는 것: 훅으로 시작·보상으로 끝, dialogue beat가 있는지, 내레이션 beat 비율 40% 이하, dialogue 구간에 내레이션이 없는지, 해석은 두 번까지, 내레이션이 한 문장인지, 내레이션이 같은 beat 대사를 되풀이하지 않는지. `shots` 명령으로 `place_story_shots`에 넘길 장면 목록을, `finish` 명령으로 마무리 효과 후보를 만듭니다.

## 8. MCP 진행 순서

1. 본편 §8의 1–3번(확인, 사전 조사, 대사 뽑기, 장면 나누기, 알아보기, 로고 띠)을 그대로.
2. 쇼츠로 쓸 상황 후보 2–3개를 고르고(§2), 후보마다 첫 대사·마지막 터지는 대사·예상 길이를 보여 주고 하나를 고르게 합니다.
3. beat 표(§7)를 쓰고 §4로 내레이션 넣을 곳을 정해 검사 → 사용자 확인.
4. `place_story_shots { clipId, shots, crop }`(대사 beat는 `keyLine`으로 원본 소리 살림) → `apply_shorts_layout`(§6.1, 9:16 위 띠 제목 · 영상 · 아래 띠 작품명) → 내레이션은 `needsNarration`인 beat에만 `ai.voice.generate` → `check_voice_consistency` → 대사 자막·내레이션 자막 → BGM은 아주 낮게(대사 구간 −18dB 이하).
5. 마무리 효과 패스(`recap-highlight.md` §8.2): `check_recap_plan` 결과 `finishing`을 보고 효과음·전환·모션그래픽이 필요한 곳에만 넣음. 쇼츠는 대사 위에 효과음을 얹지 않고, 해석 줄 끝 팝·터지는 대사 직후 스팅·핵심어 팝(beat `keyword`) 정도 → 검수.

## 9. 검수 체크리스트

- [ ] 한 상황·한 갈등만 다루고, 첫 1초에 말이나 소리가 있다.
- [ ] 대사만으로 이해되는 구간에는 내레이션이 없고, 내레이션 beat가 40% 이하다.
- [ ] 내레이션은 문장마다 역할 하나이고 대사 내용을 되풀이하지 않는다.
- [ ] 마지막이 반전·황당한 대사·통쾌한 행동으로 끝난다.
- [ ] 대사가 중간에 잘리지 않고, 대사 구간 원본 소리가 또렷하다(BGM이 가리지 않음).
- [ ] 누구인지·무슨 상황인지 화면으로 알 수 있는 장면만 썼다(본편 §1.1).
- [ ] 9:16이면 위 띠 훅 제목(1–2줄, 한 줄 12자 안팎)·가운데 영상·아래 띠 작품명이 겹치지 않고, 로고는 사용자가 준 것만 썼다(§6.1).
- [ ] 효과음·전환·모션그래픽은 이유가 있는 곳에만 있다(본편 §8.2).
